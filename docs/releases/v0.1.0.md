# PassText Core v0.1.0

> Release-note draft. No tag, GitHub Release, or crates.io publication has been
> created. Publication remains subject to owner approval, a project license,
> and successful final verification of the tagged commit.

PassText Core is the Rust implementation of the PassText Python reference
library. This first development milestone provides a focused, Unicode-aware
foundation for preparing password text before a separate analysis system uses
it.

## Highlights

- Unicode-aware password preparation preserves empty strings, whitespace,
  mixed scripts, combining marks, and emoji without lossy decoding.
- Strict typed validation rejects malformed UTF-8, invalid Unicode scalar
  values, invalid configuration, processing-limit violations, and invalid
  scalar or byte indices without including password text in errors.
- Configurable limits bound both UTF-8 bytes and Unicode scalar values before
  and after normalization.
- Explicit NFC normalization is opt-in and pinned to Unicode 16.0.0; the default
  mode preserves the input exactly.
- Content-free metadata records original and processed lengths, non-ASCII
  presence, normalization mode, and whether normalization changed the text.
- Safe Unicode indexing converts between scalar positions and UTF-8 byte
  boundaries and slices half-open scalar ranges.
- Rust ownership preserves borrowed storage, moves owned storage, and retains a
  second representation only when NFC changes the input. This reduces avoidable
  copying but is not a secure-erasure guarantee.
- Shared fixtures and a deterministic 214-case differential corpus verify
  behavioral parity with the Python reference on matching Unicode 16.0.0 data.
- The core compiles for `wasm32-unknown-unknown` without a platform-specific
  runtime dependency. JavaScript and Python bindings are not included.

## Install and use

After owner approval and crates.io publication:

```toml
[dependencies]
passtext-core = "0.1.0"
```

The crate uses the Rust 2021 edition, and CI tracks stable Rust. This candidate
is locally verified with `rustc 1.96.0`; no minimum supported Rust version is
declared yet.

```rust
use passtext_core::{process_password, NormalizationMode, PassTextConfig};

fn main() -> Result<(), passtext_core::PassTextError> {
    let config = PassTextConfig::new(4096, 1024, NormalizationMode::Nfc)?;
    let prepared = process_password("e\u{301}", config)?;

    assert_eq!(prepared.processed_text(), "é");
    assert_eq!(prepared.metadata().original_codepoints(), 2);
    Ok(())
}
```

The [API guide](../api.md) documents the borrowed, owned, byte, code-point, and
indexing entry points.

## Security and compatibility limits

PassText Core keeps diagnostics and metadata free of password contents, forbids
unsafe Rust, and returns typed errors for ordinary invalid input. These design
controls and tests are not an independent security audit.

Prepared values deliberately expose and retain password text for downstream
processing. The crate cannot zeroize borrowed input and does not promise secure
erasure of owned immutable strings. Callers remain responsible for preventing
logging, serialization, crash-dump, swap, and persistence exposure.

Python interpreters with a Unicode database older than 16.0.0 can normalize
new or version-sensitive characters differently. Shared long-stable fixtures
remain compatible, while exhaustive differential parity requires matching
Unicode data versions.

This release does not provide strength scoring, dictionary or guessability
analysis, compromised-password screening, authentication, password hashing,
site policy, or JavaScript/Python bindings. See the [security
guide](../security.md) and [Unicode compatibility
guide](../unicode-compatibility.md) for the complete boundary.
